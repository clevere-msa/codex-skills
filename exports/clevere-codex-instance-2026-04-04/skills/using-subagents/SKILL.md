# Skill: Using Subagents (Supervisor → Worker via `codex exec`)

## Purpose
Enable the current Codex agent (Supervisor) to delegate bounded tasks to one-off worker runs (“subagents”) using `codex-subagent`, with deterministic file-based I/O and per-agent continuity ledgers.

## Capability Note (Mandatory)
Subagents are not a built-in tool. They are spawned by running a separate Codex process via the shell:
- `codex-subagent run ...` (preferred), or
- `codex exec ...` directly

If this session cannot run shell commands (or the helper scripts are not installed in PATH), then subagents are not available and the Supervisor must not propose them.

## Preconditions
- The current agent session is started via the `codex` wrapper that sets:
  - CODEX_AGENT_ID
  - CODEX_AGENT_DIR
  - CODEX_LEDGER
  - CODEX_RUNS_DIR
- The helper script `codex-subagent` exists in PATH and is executable.

## Core Rule: No Implicit Context
Subagents must NEVER assume they have the Supervisor’s conversational context.
All context must be explicitly provided through:
1) the task packet (input.md)
2) the Supervisor’s continuity ledger (path in CODEX_LEDGER)
3) repository files (only if referenced)

## When to Spawn a Subagent
Spawn a subagent when at least one is true:
- The task is parallelizable (research vs implementation vs testing).
- The task is specialized or long-form (deep dive, log triage, doc drafting).
- The task can be expressed as a bounded packet with clear deliverables.
- You need an independent run to reduce cognitive load or avoid context mixing.

Do NOT spawn subagents for trivial steps that can be completed immediately.

## Standard Subagent Invocation Pattern
Use codex-subagent run <slug> with the task body on stdin:

cat <<'EOF' | codex-subagent run <slug>
# Task
<what to do>

## Context
- Read the continuity ledger at: $CODEX_LEDGER
- Read any referenced repo files: <paths>

## Constraints
- Deterministic, implementation-ready output
- No secrets in outputs
- Do not modify files unless explicitly instructed

## Deliverables
- Write results to output.md
- If proposing code changes, also write patch.diff (optional)
EOF

If you need to pass Codex args to the worker, use the -- delimiter:

cat <<'EOF' | codex-subagent run <slug> -- --full-auto
...
EOF

## Output Contract (Mandatory)
A subagent run is considered successful only if it produces:
- output.md (required)

Recommended optional outputs:
- patch.diff (if code changes are proposed)
- artifacts/ directory (if multiple files are produced)

The Supervisor must treat output.md as the primary deliverable.

## Ledger Contract (Per-Agent Working Memory)
- The continuity ledger is per-running-agent and located at CODEX_LEDGER.
- Subagents may append to the ledger ONLY if instructed in the packet and ONLY as append-only notes.
- Subagents must not rewrite or refactor the entire ledger.
- The Supervisor remains the final authority on ledger curation.

## Supervisor Post-Processing Checklist
After a subagent completes:
1) Read the worker’s output.md.
2) Validate claims and check for hallucinations.
3) If patch.diff exists, inspect before applying.
4) Decide:
   - accept/reject recommendations
   - integrate into the Supervisor plan
5) Update the continuity ledger if the result changes shared state.

## Failure Handling
If the subagent output is missing or low quality:
- Re-run with a tighter packet:
  - narrower scope
  - explicit assumptions
  - explicit deliverables
  - explicit “do not do X” constraints
- If the worker hit tool errors, include:
  - the error excerpt
  - the intended command
  - the expected file paths

## Security Requirements
- Never include secrets in task packets.
- Never request a worker to type or reveal passwords.
- Prefer storage-state or test auth bypass for browser automation.
- If any output might contain secrets, stop and escalate to the Supervisor for redaction.

## Directory and ID Conventions
- Each run is stored under: $CODEX_RUNS_DIR/<TASK_ID>/
- <TASK_ID> is auto-generated by codex-subagent.
- The Supervisor should reference task outputs via the paths printed by codex-subagent.

## Prohibited Behaviors
- Assuming shared conversation context across processes
- Writing to another agent’s ledger
- Unbounded tasks without deliverables
- Secret handling through echoed channels
